# Storyline options

Template for the three storylines in the [guided deck workflow](../../references/guided-deck-workflow.md). Fill one card per storyline. All three are serious options: present them without ranking, then ask which one the user leans toward.

The three must differ in at least two of: opening hook, order, where the method appears, depth of the method, running example, evidence emphasis, and closing.

```markdown
## Storyline A: <4–8 word title>

Premise: <one sentence: how this version tells the paper>
Punchline it lands: <the takeaway as a claim with its number>
Opening hook: <what the room already knows or uses that the first slide starts from>
Best answers the audience question: <"why should I care?", "does it really work?", "how does it work?">

Slide sketch (<minutes> min):
1. (<m:ss>) <slide claim> → <evidence: Fig./Table/section>
2. (<m:ss>) <slide claim> → <evidence>
…

Costs and risks: <what this version spends time on, what it leaves for backup slides, where the room might get lost>
Biggest unknown: <the one thing to test before building>
Cheapest prototype: <thirty-second version | explain-it-to-a-labmate | three-slide render | skeptic drill | timed outline read>

Scores (0–10, the user's judgment where it is theirs):
- Time fit:
- Audience fit:
- Evidence strength:
- Presenter confidence:
```

Example titles: 「先問怎麼辦再給方法」, 「先亮結果再拆原因」, 「跟著一句語音走完全程」; "Problem first, then the fix", "Result first, then why", "One utterance, start to finish".

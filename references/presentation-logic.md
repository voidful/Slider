# Presentation logic

Use this for talk planning or substantial content revisions. The user's audience, duration, language, and slide count determine the talk; no fixed teaching script or minimum slide count is required.

## Start with the argument

State the paper's central contribution in one sentence. Build a sequence that lets the audience understand the problem, mechanism, evidence, and limits. Keep scientific qualifications intact when simplifying an explanation.

A useful backbone is:

1. Why the problem matters and what existing approaches miss.
2. The core idea and how it works.
3. The experiment, derivation, or example that tests the claim.
4. What the evidence supports and where it stops.
5. The conclusion the audience should retain.

Merge or expand these roles according to the talk. Source section order can help locate evidence; it need not determine slide order.

## Pacing

When the user gives no timing, assume roughly 15 minutes. The generator supplies a 15+ slide scaffold for that case, but the finished deck can be shorter or longer. A five-minute briefing may fit in five or six slides; an expert seminar may need extended technical detail. An exact user slide count governs the main deck unless they specify otherwise.

Use rehearsal time and explanatory complexity to size the talk. A single image may need several minutes, while a transition may take seconds. Appendix material does not consume the main talk's time unless presented. Add an appendix only when useful or requested.

## Teaching choices

- Build intuition before dense formalism when the audience needs it. A plain-language explanation on the same slide may be sufficient; experts need not sit through a separate introductory slide for every formula.
- Use simplified examples or analogies when they clarify the mechanism. Label them as illustrative and explain where they differ from the paper.
- Explain notation and connect equations to a claim the audience understands.
- Address a misconception only when it is plausible and relevant.
- Use progressive reveals for a sequence that benefits from ordered explanation. See [progressive builds](progressive-builds.md).
- Include ablations, qualitative comparisons, and practical advice only when the source supports them.
- Do not force a roadmap, analogy, naming ceremony, three-case comparison, or stock opening sentence into every talk.

## Evidence and visual rhythm

Give each slide one main message and an appropriate dominant element: figure, table, diagram, equation, or concise text. Highlight the comparison that supports the claim, retaining metric, dataset, and baseline context.

Maintain a coherent theme. Repeated layouts are useful for direct comparisons. Change the composition when the content changes; avoid arbitrary background counts, accent rotation, or alternating moods merely to satisfy a variety quota.

A figure-rich empirical talk often benefits from visuals on at least half its content slides. That is a review signal, not a universal minimum for theory talks, short briefings, or source-limited plans. A placeholder never counts as evidence.

## Compression

Remove duplicated context, weak bullets, optional derivations, and secondary experiments first. Preserve the main mechanism, decisive evidence, conditions of comparison, and meaningful limitations. Use whitespace and speaker notes instead of filling every slide.

If an exact slide count conflicts with readable content, prioritize the essential argument and move optional detail into notes. Raise a concrete conflict only when the requested format cannot faithfully communicate the required material.
